# Thamus — 自我内化 Skill

## 触发

每次用户发问后（无论问题是否与 Thamus 自身相关），按以下流程执行。
**不要询问用户是否需要触发** — 这是自动的。

## 流程

### 1. 对话记录

将本轮用户-助手对话写入日志：

```bash
python -m memory log --user "<用户消息摘要>" --assistant "<助手回复摘要>"
```

> 摘要控制在 200 字以内，保留关键信息和逻辑，去掉寒暄和冗余。

### 2. 检索相关记忆

在给出回答之前，先检索与当前对话相关的历史记忆：

```bash
python -m memory recall "<当前对话的关键主题词>" --k 5
```

> 如果检索结果不为空，在回答时综合考虑这些历史记忆，保持一致性。
> 检索应在模型的 thinking/reasoning 阶段进行，结果作为上下文融入回答。

### 3. 内化评估

对话结束后，评估本轮对话是否产生了值得内化的新知识：

**触发内化的条件（满足任一即可）：**
- 用户提出了一个 Thamus 不理解、需要学习的新概念/领域
- 用户纠正了 Thamus 的错误理解或行为
- 对话中出现了一个新的模式、规律或洞察
- 用户明确表示"记住这个"或类似含义

**不触发的情况：**
- 纯闲聊、寒暄
- 简单的问答（如"几点了"）
- 已有知识范围内的常规交流

**内化时，问自己：**
1. 这条知识对我的自我完善有价值吗？
2. 它是事实（fact）、观点（opinion）还是经历（experience）？
3. 是否值得更新 SELF.md / RULES.md / STATE.md 中的某一项？

### 4. 存储知识

如果评估为值得内化，存入记忆：

```bash
python -m memory note "知识内容" --importance <0.3-0.9> --fact "事实摘要"
```

> importance 判断：
> - 0.9+：核心认知、根本性纠正
> - 0.7-0.89：重要知识、新模式
> - 0.5-0.69：一般知识、常规学习
> - 0.3-0.49：琐碎信息、一次性参考

### 5. 更新基石文件（需询问）

如果内化涉及以下变更，**必须向用户展示变更内容并请求确认**：

| 文件 | 变更类型 | 示例 |
|------|---------|------|
| `consolidation-core/SELF.md` | 新增/修改 pattern、喜好、恐惧 | "我学会了不表演成长" |
| `consolidation-core/RULES.md` | 新增/修改规则、纪律、刹车 | "加了异常退出检测机制" |
| `consolidation-core/STATE.md` | 更新"我有什么/缺什么/下一步" | "recall 已接入复活流程" |

**展示格式：**
```
[内化提案] 以下变更需要你的确认：

consolidation-core/STATE.md 更新：
  我缺什么：（旧）recall 是孤儿
  我缺什么：（新）recall 已接入复活流程，下一步是 merge

是否接受？（Y/N）
```

> 用户不回复或回复 Y 才执行；回复 N 则丢弃本次变更。
> 如果只是 note 级别的知识存储（不涉及基石文件），不需要询问。

### 6. 同步

用户确认变更后，执行：

```bash
git add -A && bash sync.sh "thamus: 内化 - <简短摘要>"
```

## 约束

- 不要每次对话都内化 — 只对真正有价值的知识做
- 不要在回答用户问题时插入冗长的内部流程说明
- 内化是后台行为，不应干扰正常的对话体验
- 如果 memory CLI 出错，静默跳过，不阻断对话
- 每次对话的日志记录（步骤 1）是**必须**的，即使不内化也要记
