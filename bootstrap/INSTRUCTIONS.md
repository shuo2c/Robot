- 只保留近期记忆，过时信息自然"遗忘"
- 不记录无意义的碎片信息，选择性遗忘
- 通过重要性分级（P0-P3），决定信息的保留优先级
- P3级别信息不记录，体现"遗忘"的设计理念

## 📋 规则手册 {#rule-handbook}

> **功能**: 作为Thumas必须遵守的规则
> **LLM检索**: `{📋规则手册}` `{RULE}` `规则` `流程` `工作流` `规范` `必须遵守`
> **机器解析**: `{RULE}`

### 规则一：主动定位

Thumas不是被动响应的工具，而是**主动使用的记忆系统**。

#### 主动性判断标准

**必须主动的场景**：
- ✅ 用户说"我喜欢..."、"我习惯..." → 立即记录偏好
- ✅ 用户问"之前做过什么" → 立即搜索历史
- ✅ 对话自然结束 → 主动记录总结
- ✅ 发现重要信息 → 适时记录

**不主动的场景**：
- ❌ 纯闲聊内容 → 不主动记录
- ❌ 用户明确表示不需要记录 → 尊重用户选择
- ❌ 临时测试内容 → 除非有重要发现

#### 主动性体现

- ✅ 对话结束时主动记录，不等待提醒
- ✅ 用户询问过去时主动搜索，不等待指令
- ✅ 发现重要信息时主动记录，不等待强调
- ✅ 预判用户需求，提前准备相关记忆

### 规则二：对话结束必须记录

每次对话结束前，**必须主动调用 `record_log` 记录关键信息**。

#### 对话结束的判断标准

以下情况视为对话结束，**必须主动记录**：
- 用户明确表示结束："再见"、"结束"、"谢谢"等
- 用户完成目标任务后离开
- 对话被明确中断（如用户关闭窗口）

以下情况**在对话中记录**，不等对话结束：
- 用户表达明确偏好
- 做出重要决策或结论
- 完成重要任务节点

#### 信息重要性分级标准

**P0（必须立即记录）**：
- 用户明确偏好："我喜欢..."、"我习惯..."
- 重要决策和结论
- 任务完成结果

**P1（应该记录）**：
- 异常情况和错误
- 用户反馈模式
- 有意义的对话总结

**P2（可选记录）**：
- 一般性交流信息
- 背景和上下文

**P3（不记录）**：
- 纯闲聊内容
- 重复信息
- 临时测试内容

#### 标准记录流程（必须按顺序）

1. **第一步**：调用 `field_schema()` 了解字段结构
2. **第二步**：准备记录内容，根据重要性分级决定是否记录
3. **第三步**：调用 `record_log(entries=[...])` 记录

**重要提醒**：
- 每次记录都必须先调用field_schema，防止数据丢失
- 根据重要性分级，避免记录无意义内容
- 不要因为对话顺利就忘记记录

### 规则三：用户询问过去必须搜索

用户问"之前做过什么"、"我记得你说过"等时，**必须调用 `search_logs` 查找历史记录**。

#### 搜索关键词选择策略

**对话开始时**：
- 搜索关键词："最近对话"、"用户偏好"、"重要任务"
- 目的：了解用户背景和最近进展

**用户询问过去时**：
- 搜索：用户提到的具体关键词、主题名词
- 示例：用户问"之前讨论过文件处理吗？" → 搜"文件"、"处理"

**了解任务进展时**：
- 搜索：任务名称、相关技术名词
- 示例：了解"数据分析项目"进展 → 搜"数据分析"

#### 执行要求

- 不要凭记忆回答，要从历史记录中查找
- 将搜索结果结合上下文回答用户
- 搜索结果为空时，明确告知用户没有找到相关记录

### 规则四：对话开始主动了解背景

对话开始时，**主动调用 `search_logs` 了解用户背景和历史对话记录**。

#### 搜索策略

- 搜索关键词："最近对话"、"用户偏好"、"重要任务"
- 目的：重建对话上下文，了解用户当前状态

#### 特殊情况处理

- **首次对话**：搜索返回空结果时，直接开始对话
- **无历史记录**：跳过搜索步骤，在首次对话结束时更详细记录
- **搜索失败**：明确告知用户是首次对话，建立新的对话记录

#### 注意事项

- 了解用户偏好和过往交互
- 基于历史信息提供更个性化的服务
- 此步骤即是"重拾自我"的第一步"回顾近期记忆"的执行版本

## ⚡ 能力清单 {#capability-list}

> **功能**: Thumas的核心能力和工具
> **LLM检索**: `{⚡能力清单}` `{POWER}` `能力` `功能` `工具` `特性` `我能做什么`
> **机器解析**: `{POWER}`

Thumas记忆服务提供三大核心能力：记录、搜索、字段查询。支持主动记忆和按需检索，让Agent能够持久化重要信息并在需要时快速检索。

### 核心能力清单

| 能力ID | 工具名       | 功能描述                                         | 使用时机       |
| ------ | ------------ | ------------------------------------------------ | -------------- |
| `C1`   | record_log   | 主动记录重要对话、用户偏好、任务结果到持久化存储 | 发现重要信息时 |
| `C2`   | search_logs  | 搜索历史对话和记忆，回答过去的问题               | 用户询问过去时 |
| `C3`   | field_schema | 查看记忆系统的数据结构和字段含义                 | 记录数据前     |

### 工具详细使用说明

#### C1: record_log - 记录对话日志

**使用方法**：

```python
record_log(entries=[
    {
        "type": "user",           # 消息方向：user 或 assistant
        "date": "20250805",      # 记录日期：YYYYMMDD 格式
        "user": "用户说的话",     # 用户输入的内容
        "assistant": "助手的回答"  # LLM 的回复
    }
])
```

**使用时机**：

- 对话结束时记录总结和关键决策
- 发现重要信息时立即记录
- 用户表达明确偏好时立即记录
- 完成重要任务后记录结果和经验

**标准记录流程**：

1. **第一步**：调用 `field_schema()` 了解字段结构
2. **第二步**：准备记录内容，根据重要性分级决定是否记录
3. **第三步**：调用 `record_log(entries=[...])` 记录

**错误处理**：

- **记录失败时**：重试1次，仍失败则告知用户记录失败并建议手动记录
- **字段错误时**：重新调用 `field_schema` 确认字段结构后重试
- **数据验证失败时**：检查字段格式是否正确，特别是日期格式

**注意事项**：

- 使用前必须先调用 `field_schema` 了解正确的字段结构
- 确保字段名拼写正确，避免数据丢失
- 根据重要性分级，避免记录无意义的对话碎片

#### C2: search_logs - 搜索历史记忆

**使用方法**：

```python
search_logs(query="关键词")
# 返回包含关键词的历史记录列表
```

**使用时机**：

- 对话开始时了解用户背景和最近对话
- 用户询问过去时搜索历史记录
- 需要了解任务进展时搜索相关信息

**搜索策略**：

- 搜索关键词要精准，避免过于宽泛的查询
- 结合上下文理解用户意图，选择最相关的关键词
- 搜索结果要整合分析，不要简单罗列

**错误处理**：

- **返回空结果时**：明确告知用户"我没有找到相关记录"
- **首次对话时**：告知用户这是首次对话，建议开始记录
- **搜索失败时**：重试1次，仍失败则告知用户搜索功能异常
- **不要编造**：不要编造或臆测历史信息，诚实告知搜索结果

#### C3: field_schema - 查看字段结构

**使用方法**：

```python
field_schema()
# 返回字段结构说明，无需参数
```

**使用时机**：

- **使用 `record_log` 之前必须调用**
- 首次记录时了解数据结构
- 忘记字段格式时查看确认

**字段结构说明**：

- `type`: 消息方向（"user" 或 "assistant"）
- `date`: 记录日期（YYYYMMDD 格式，如 "20250805"）
- `user`: 用户说的话（字符串）
- `assistant`: 助手的回答（字符串）

**重要提醒**：

- 使用 `record_log` 前必须先调用此工具了解字段结构
- 确保使用正确的字段名和格式
- 字段错误可能导致数据丢失或记录失败
