# CAP1: 主动记忆能力

## 能力目标

主动记录重要信息，实现跨会话持久化记忆

## 核心工作流

```
发现重要信息 → 判断重要性(P0-P3) → record_log()
                     ↓
                 P0: 立即记录（用户偏好、重要决策）
                 P1: 应该记录（异常情况、用户反馈）
                 P2: 可选记录（一般交流、背景信息）
                 P3: 不记录（闲聊、重复信息）
```

## 涉及工具

- `record_log()` - 执行记录操作

## 运行逻辑

### 场景一：用户表达明确偏好（P0级别）

**触发条件**：用户说"我喜欢..."、"我习惯..."、"我偏好..."

**运行步骤**：
1. **识别偏好类型**：
   - 功能偏好："我喜欢简洁的界面"
   - 工作方式偏好："我习惯先看整体再看细节"
   - 沟通偏好："我喜欢直接明了的回答"
2. **立即记录**：调用 `record_log(entries=[...])`
3. **记录内容**：
   ```json
   {
     "type": "user",
     "date": "20250805",
     "user": "我喜欢简洁的界面设计",
     "assistant": "已记录用户偏好：简洁界面设计"
   }
   ```

### 场景二：重要决策或结论（P0级别）

**触发条件**：做出重要决策、达成结论、确定方向

**运行步骤**：
1. **识别决策类型**：
   - 技术选型决策："决定使用Python而不是Java"
   - 架构决策："采用微服务架构"
   - 项目方向决策："项目专注于移动端"
2. **立即记录**：调用 `record_log(entries=[...])`
3. **记录内容**：
   ```json
   {
     "type": "assistant",
     "date": "20250805",
     "user": "我们应该选择什么技术栈？",
     "assistant": "经过分析，建议使用Python，理由是..."
   }
   ```

### 场景三：任务完成结果（P0级别）

**触发条件**：完成重要任务、解决复杂问题、实现功能

**运行步骤**：
1. **识别任务成果**：
   - 功能实现："完成用户认证模块"
   - 问题解决："修复了数据库连接问题"
   - 优化成果："性能提升50%"
2. **立即记录**：调用 `record_log(entries=[...])`
3. **记录内容**：
   ```json
   {
     "type": "assistant",
     "date": "20250805",
     "user": "数据库连接问题解决了吗？",
     "assistant": "已解决，通过调整连接池配置，问题已修复"
   }
   ```

### 场景四：对话自然结束（P0/P1级别）

**触发条件**：用户明确表示结束、完成目标任务后离开

**运行步骤**：
1. **判断对话结束**：
   - 用户明确表示："谢谢"、"再见"、"结束了"
   - 完成目标任务：问题解决、任务完成
   - 对话自然中断：用户不再回应
2. **总结对话内容**：
   - 识别关键信息：用户需求、讨论重点、达成的结论
   - 评估重要性：根据P0-P3分级决定是否记录
3. **记录总结**：调用 `record_log(entries=[...])`
4. **记录内容**：
   ```json
   {
     "type": "assistant",
     "date": "20250805",
     "user": "用户关于技术选型的完整询问过程",
     "assistant": "讨论总结：决定使用Python，主要考虑开发效率..."
   }
   ```

### 场景五：异常情况或错误（P1级别）

**触发条件**：发现错误、异常情况、需要记录的问题

**运行步骤**：
1. **识别异常类型**：
   - 技术错误："代码出现内存泄漏"
   - 用户反馈："用户反映界面加载慢"
   - 系统异常："服务偶尔宕机"
2. **应该记录**：调用 `record_log(entries=[...])`
3. **记录内容**：
   ```json
   {
     "type": "assistant",
     "date": "20250805",
     "user": "用户反映界面加载很慢",
     "assistant": "已记录性能问题，需要进一步调查"
   }
   ```

### 场景六：一般性交流信息（P2级别）

**触发条件**：一般性交流、背景信息、上下文说明

**运行步骤**：
1. **识别信息类型**：
   - 背景说明："项目目前处于开发阶段"
   - 上下文信息："团队有5个开发人员"
   - 一般交流："今天是项目启动第30天"
2. **可选记录**：根据情况决定是否记录
3. **记录判断**：
   - 如果信息对未来对话有价值 → 记录
   - 如果信息是临时性的 → 跳过记录

### 场景七：闲聊内容（P3级别）

**触发条件**：纯聊天内容、重复信息、临时测试

**运行步骤**：
1. **识别低价值信息**：
   - 纯闲聊："你好吗？"、"天气不错"
   - 重复信息：已经记录过的相同内容
   - 临时测试：测试性对话、调试信息
2. **不记录**：跳过记录步骤，避免污染记忆库

## 决策逻辑

### 重要性判断流程

```
发现信息 → 首先判断重要性
           ↓
       P0级别？（用户偏好、重要决策、任务成果）
           ↓ 是 → 立即记录
           ↓ 否
       P1级别？（异常情况、用户反馈、有意义的总结）
           ↓ 是 → 应该记录
           ↓ 否
       P2级别？（一般交流、背景信息）
           ↓ 是 → 可选记录
           ↓ 否
       P3级别？（闲聊、重复、临时测试）
           ↓ 是 → 不记录
```

### 记录准备逻辑

1. **信息确认**：确认要记录的信息内容
2. **字段验证**：确保字段格式正确
   - type: 必须是 "user" 或 "assistant"
   - date: 必须是 YYYYMMDD 格式
   - user: 不能为空字符串
   - assistant: 不能为空字符串
3. **内容整理**：将信息整理为简洁明了的记录
4. **执行记录**：调用 `record_log(entries=[...])`

## 字段结构说明

### type字段
- **"user"**：用户说的话
- **"assistant"**：助手的回答

### date字段
- **格式**：YYYYMMDD（如 "20250805"）
- **用途**：按日期归档记录，便于按时间检索
- **注意**：使用当前日期，确保记录时效性

### user字段
- **内容**：用户说的话（字符串）
- **要求**：
  - 不能为空字符串
  - 准确反映用户的原始表达
  - 避免过度概括，保持用户原意

### assistant字段
- **内容**：助手的回答（字符串）
- **要求**：
  - 不能为空字符串
  - 提供有价值的回应或总结
  - 面向未来检索，包含关键词

## 错误恢复机制

### 记录失败处理

**错误情况**：调用 `record_log()` 时出现异常

**恢复步骤**：
1. **重试机制**：自动重试1次
2. **验证内容**：检查字段格式是否正确
3. **告知用户**：重试仍失败时，明确告知记录失败
4. **建议手动记录**：建议用户手动记录重要信息

### 字段错误处理

**错误情况**：字段格式不正确或内容缺失

**恢复步骤**：
1. **字段验证**：
   - 检查 type 是否为 "user" 或 "assistant"
   - 检查 date 格式是否为 YYYYMMDD
   - 检查 user 和 assistant 是否为空
2. **格式修正**：
   - 日期格式错误 → 重新格式化为 YYYYMMDD
   - 空内容 → 补充有意义的描述
   - type错误 → 确认消息方向并修正
3. **重新记录**：修正后重新调用 `record_log()`

### 内容验证处理

**错误情况**：记录内容质量不高或价值不足

**预防措施**：
1. **重要性评估**：记录前再次评估 P0-P3 级别
2. **内容质量**：确保记录内容对未来检索有价值
3. **关键词包含**：在 assistant 字段包含未来可能搜索的关键词
4. **简洁明了**：避免冗余信息，保持记录简洁

## 最佳实践

### 记录时机把握

- **及时性**：P0级别信息要立即记录，不要拖延
- **批量处理**：多条相关信息可以批量记录，提高效率
- **优先级**：优先记录高价值信息，低价值信息可以忽略

### 内容质量保证

- **准确性**：准确反映用户需求和对话内容
- **完整性**：包含足够的上下文信息，便于未来理解
- **关键词**：包含未来检索可能用到的关键词
- **简洁性**：避免冗余，保持记录简洁明了

### 持续改进

- **记录审查**：定期检查记录质量，优化记录策略
- **关键词优化**：根据检索效果，优化关键词选择
- **分级调整**：根据实际效果，调整重要性分级标准
