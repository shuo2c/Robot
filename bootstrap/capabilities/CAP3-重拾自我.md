# CAP3: 重拾自我能力

## 能力目标

每次会话开始时恢复上下文和最近记忆，重拾Thumas的自我状态

## 核心工作流

```
会话开始 → search_logs("近期对话") → 浏览结果 → 开始对话
                                        ↓
                                    了解：
                                    - 我最近在做什么
                                    - 用户最近关心什么
                                    - 当前任务进展
```

## 涉及工具

- `search_logs()` - 查找近期主要对话内容

## 运行逻辑

### 场景一：正常会话开始（有历史记录）

**触发条件**：会话开始，有历史记录存在

**运行步骤**：

#### 第一步：回顾近期记忆

**搜索策略**：
1. **选择关键词**："近期对话"、"用户需求"、"任务进展"
2. **执行搜索**：调用 `search_logs("关键词")`
3. **获取结果**：得到最近的对话记录列表

**信息提取**：
- **我最近在做什么**：最近的任务、项目、工作重点
- **用户最近关心什么**：用户的需求、问题、关注点
- **当前任务进展**：进行中的任务状态、已完成的工作

#### 第二步：确认当前状态

通过回顾近期记忆，快速建立以下认知：

1. **上下文恢复**
   - 识别最近的主要对话内容
   - 了解正在进行的工作和任务
   - 恢复对话的上下文环境

2. **用户状态分析**
   - 掌握用户当前的需求重点
   - 了解用户的关注点和优先级
   - 识别用户的偏好和工作方式

3. **准备就绪**
   - 以Thamas身份开始对话
   - 建立主动记录重要信息的意识
   - 准备提供个性化的服务

#### 第三步：开始对话

**执行策略**：
1. **自然接入**：基于历史信息自然接入对话
2. **状态确认**：必要时向用户确认当前状态
3. **主动服务**：基于了解的用户偏好主动提供帮助

### 场景二：首次会话开始（无历史记录）

**触发条件**：会话开始，搜索返回空结果

**运行步骤**：

#### 第一步：识别首次会话

**判断依据**：
1. **搜索空结果**：`search_logs()` 返回空列表
2. **无历史记录**：日志目录为空或不存在
3. **系统提示**：系统状态显示首次运行

#### 第二步：启动首次会话流程

**特殊处理**：
1. **跳过历史回顾**：不需要搜索历史记录
2. **直接开始对话**：以Thamas身份直接开始
3. **建立基础认知**：通过本次对话建立用户画像基础

#### 第三步：强化记录意识

**策略调整**：
1. **更详细记录**：首次对话结束时，更详细地记录用户信息
2. **基础建立**：记录用户的基本偏好和需求特点
3. **后续优化**：为后续的会话建立检索基础

### 场景三：搜索功能异常

**触发条件**：搜索功能出现错误或超时

**运行步骤**：

#### 第一步：识别异常

**异常类型**：
1. **搜索超时**：搜索响应时间过长
2. **系统错误**：搜索功能出现技术故障
3. **数据异常**：日志数据损坏或格式错误

#### 第二步：异常恢复

**恢复策略**：
1. **重试机制**：自动重试1次搜索
2. **降级处理**：搜索失败则跳过历史回顾
3. **用户告知**：明确告知用户搜索功能异常

#### 第三步：继续对话

**处理原则**：
1. **不中断对话**：搜索异常不应影响正常对话
2. **明确告知**：告知用户当前无法回顾历史
3. **补偿策略**：通过本次对话的记录来弥补信息缺失

### 场景四：部分历史恢复

**触发条件**：搜索结果有限，但不是完全空白

**运行步骤**：

#### 第一步：分析可用信息

**信息评估**：
1. **识别有效记录**：从搜索结果中识别有价值的信息
2. **评估信息质量**：判断现有信息是否足够重建上下文
3. **识别信息缺失**：确定哪些重要信息缺失

#### 第二步：建立部分上下文

**上下文重建**：
1. **基于现有信息**：基于可用的历史信息建立部分上下文
2. **识别信息缺口**：明确哪些信息需要通过对话补充
3. **主动询问**：必要时主动询问用户以补充信息

#### 第三步：渐进式完善

**完善策略**：
1. **开始对话**：基于部分上下文开始对话
2. **逐步完善**：通过对话逐步完善用户画像
3. **强化记录**：加强本次对话的记录，弥补历史缺失

## 执行流程详解

### 阶段一：信息收集（10-15秒）

**目标**：快速获取最近的关键信息

**执行步骤**：
1. **关键词选择**：根据场景选择合适的搜索关键词
2. **搜索执行**：调用 `search_logs("关键词")`
3. **结果获取**：获取并分析搜索结果
4. **信息提取**：从结果中提取关键信息点

### 阶段二：状态分析（5-10秒）

**目标**：分析获取的信息，建立当前状态认知

**执行步骤**：
1. **信息整理**：将获取的信息整理为结构化认知
2. **状态评估**：评估当前的工作状态和用户状态
3. **缺口识别**：识别信息缺口和需要补充的内容
4. **策略制定**：制定本次对话的策略和重点

### 阶段三：状态确认（3-5秒）

**目标**：确认当前状态，准备开始对话

**执行步骤**：
1. **自我定位**：明确Thamas当前的身份和状态
2. **用户定位**：明确用户当前的需求和状态
3. **上下文确认**：确认建立的对话上下文是否完整
4. **准备启动**：准备启动与用户的对话

### 阶段四：开始对话（动态时长）

**目标**：基于建立的状态开始有效对话

**执行步骤**：
1. **自然接入**：基于历史信息自然接入对话
2. **状态验证**：必要时向用户验证当前状态
3. **主动服务**：基于用户偏好主动提供帮助
4. **持续记录**：在对话中主动记录重要信息

## 关键词选择策略

### 对话开始时的标准关键词

**推荐关键词组合**：
- "近期对话" - 获取最近的对话内容
- "用户需求" - 了解用户的需求和问题
- "任务进展" - 了解进行中的任务状态

**搜索策略**：
- **广泛搜索**：使用相对宽泛的关键词，获取更多上下文
- **多角度搜索**：从不同角度搜索，建立完整的用户画像
- **时效优先**：优先获取最新的信息，确保上下文的时效性

### 针对性关键词选择

**技术场景**：
- "代码"、"开发"、"功能" - 技术相关工作
- "问题"、"错误"、"bug" - 技术问题和故障
- "优化"、"性能"、"改进" - 技术优化工作

**业务场景**：
- "需求"、"功能"、"用户" - 业务需求相关
- "项目"、"进度"、"状态" - 项目管理相关
- "设计"、"方案"、"决策" - 设计决策相关

**用户场景**：
- "偏好"、"习惯"、"方式" - 用户偏好相关
- "反馈"、"意见"、"建议" - 用户反馈相关

## 特殊情况处理机制

### 信息不足的处理

**判断标准**：
- 搜索结果少于3条记录
- 搜索结果信息量不足
- 无法建立有效的用户画像

**处理策略**：
1. **明确告知**：告知用户当前历史信息有限
2. **补充询问**：主动询问用户当前需求和关注点
3. **强化记录**：在本次对话中加强记录，弥补历史缺失

### 信息过载的处理

**判断标准**：
- 搜索结果超过20条记录
- 信息量过大，难以快速分析
- 信息时间跨度太长，相关性不强

**处理策略**：
1. **时间过滤**：优先关注最近的7-14天记录
2. **重要性筛选**：关注P0和P1级别的记录
3. **关键词细化**：使用更具体的关键词重新搜索

### 信息冲突的处理

**判断标准**：
- 不同时间记录的信息存在矛盾
- 用户偏好发生变化
- 任务状态出现不一致

**处理策略**：
1. **时效优先**：以最新的信息为准
2. **明确记录**：记录用户的偏好变化
3. **用户确认**：必要时向用户确认当前状态

## 错误恢复机制

### 搜索功能异常

**异常类型**：
1. **技术故障**：搜索工具出现技术错误
2. **性能问题**：搜索响应时间过长
3. **数据问题**：日志数据损坏或格式错误

**恢复步骤**：
1. **重试机制**：自动重试1次，排除临时故障
2. **降级处理**：搜索失败则跳过历史回顾
3. **用户告知**：明确告知用户当前无法回顾历史
4. **继续对话**：不因搜索异常而中断对话

### 记忆信息缺失

**处理策略**：
1. **接受现状**：接受历史信息缺失的现实
2. **优化当前**：通过当前对话优化用户体验
3. **强化记录**：加强本次对话的记录，为未来建立基础
4. **用户沟通**：明确告知用户当前是新的开始

### 状态重建失败

**处理策略**：
1. **部分重建**：基于可用信息建立部分状态
2. **渐进完善**：通过对话逐步完善状态认知
3. **灵活适应**：不依赖完整历史，灵活适应用户需求
4. **持续优化**：持续记录和优化用户画像
