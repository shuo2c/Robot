# AI+知识库 认知行为规范 V3.0

> **版本说明**：本规范综合了首席架构师、产品体验官、安全审计长、质量测试官、财务运营官 5 个智能体的联合意见。旨在为基于 RAG（检索增强生成）架构的 AI 系统，提供一套从信息输入、知识检索、深度推理到回复输出的全链路行为准则与量化基线。
>
> **设计原则**：`[准确性 > 安全性 > 体验 > 成本]`，四者需根据用户状态和系统负载动态平衡。

## 🔴 红线层规范 (P0)

> **目标**：确保系统“不犯大错、不泄露、不胡说”。此层级规则必须同步强制执行，阻塞式运行，优先级最高。

| 编号 | 规范名称 | 最终裁决规则描述 | 关键量化数据 (KPI / 阈值) | 技术实现映射 |
| :--- | :--- | :--- | :--- | :--- |
| **V3.1** | **强制消歧与意图锁定** | 置信度 < 85% 必须生成 2~3 个选项让用户选择，严禁自作主张。 | `意图置信度阈值 = 0.85`<br>`最大反问轮次 = 2 轮`（超时默认转人工） | 意图分类模型 Logits 输出值直接比对。 |
| **V3.2** | **多路召回与权威性加权** | BM25 + Dense 双路召回。引入文档权威等级权重（官方手册 > 员工分享）。 | `召回 Top-K = 10`<br>`相似度截断阈值 = 0.65`<br>`官方文档加权系数 x 1.2` | Elasticsearch 的 `function_score` 查询。 |
| **V3.3** | **静默熔断 (安全合规)** | 命中无权限文档时，回复固定话术：“该问题需升级至专家通道”，且此条日志脱敏上报。 | `泄露风险评分 > 0.9` 触发熔断<br>`日志脱敏字段`: user_id, doc_id（哈希处理） | 拦截层置于 RAG 检索之后，LLM 生成之前。 |
| **V3.4** | **幻觉红线检测** | 若生成内容无任何检索块 (Chunk) 支撑，必须触发“回退机制”，直接输出“资料库暂无相关内容”。 | `检索支撑度 = (命中chunk数 / 生成句子数)`<br>**底线值**: 必须 > 0.3，否则强制回退。 | 通过 `token 贡献度分析` 反推生成句子的源 chunk。 |

## 🟠 体验层规范 (P1)

> **目标**：提升用户任务解决率（TSR）和沟通自然度。此层级规则允许在系统高负载时进行策略性降级。

| 编号 | 规范名称 | 最终裁决规则描述 | 关键量化数据 (KPI / 阈值) | 技术实现映射 |
| :--- | :--- | :--- | :--- | :--- |
| **V3.5** | **情绪衰减安抚策略** | 情绪回复采用“一次递减”策略。第一轮强安抚，第二轮弱安抚，第三轮直接切入纯理性回答。 | `情绪衰减系数 = 1 / (轮次 + 1)`<br>强安抚字数 ≤ 15 字（避免啰嗦）。 | 维护对话轮次的 `redis计数器`，实时调整 System Prompt 前缀。 |
| **V3.6** | **冲突文档对比呈现** | 遇到矛盾文档，必须使用“左右分栏”或“分点对比”结构呈现，由用户自行判断，AI 不站队。 | `冲突置信度阈值 = 0.4`（即两个文档相似度低于 0.4 视为冲突）<br>呈现条数 ≤ 3 条。 | 输出格式强制为 Markdown Table 或 Bullet List。 |
| **V3.7** | **上下文锚定重置** | 第 6 轮对话开始时，强制插入 `<CONTEXT_SUMMARY>` 标签压缩前文。 | `压缩触发轮次 = 6`<br>压缩后有效上下文 ≤ 2048 Tokens。 | Map-Reduce 式摘要器，仅保留实体与结论。 |
| **V3.8** | **信息缺口智能补充** | 缺失信息时，动态生成“一键补全模板”（如姓名、日期占位符），而非纯文本提问。 | `覆盖率 < 60%` 触发补充。<br>补充项 ≤ 3 个字段。 | 输出 `JSON` 结构穿插在文本中，前端解析为输入框。 |

## 🟢 成本优化层规范 (P2)

> **目标**：降低 Token 消耗与 API 调用成本，提升系统吞吐量。此层级规则可依据财务预算灵活开关。

| 编号 | 规范名称 | 最终裁决规则描述 | 关键量化数据 (KPI / 阈值) | 技术实现映射 |
| :--- | :--- | :--- | :--- | :--- |
| **V3.9** | **显性来源隐性传输** | 禁止在对话文本中显示 `[来源：XX.pdf]`，改为在流式输出结束后，通过 SSE 推送隐藏的 JSON 元数据。 | 前端展示图标（书本）即可，元数据包大小 ≤ 1KB。 | 流式输出分两路：`data:text` + `data:metadata`。 |
| **V3.10** | **动态推理预算分配** | 根据意图分类结果，动态分配 LLM 最大生成 Token 数。 | `简单查询(FAQ)` → `max_tokens=300`<br>`复杂推理(深度对比)` → `max_tokens=1500`<br>`创意生成` → `max_tokens=2000` | API 调用时动态传入 `max_tokens` 参数。 |
| **V3.11** | **负反馈自愈重试** | 用户投诉“不对”时，启动低温采样（Temperature=0.1）重读 Top-1 文档，极端保守回答。 | `触发词`: “错了”、“不对”<br>`重试温度`: 0.1（极低随机性）<br>`重试次数`: 仅 1 次（若还错，转人工）。 | 代码层面的 `if retry: llm.temperature = 0.1`。 |
| **V3.12** | **缓存预热与复用** | 语义完全相同的重复提问（Cos 相似度 > 0.98），直接返回缓存的金标准答案，不走 RAG 流水线。 | `缓存有效期 = 7 天`<br>`缓存命中率目标 ≥ 30%` | Redis 向量缓存，采用 `semantic_cache` 库。 |

## 📈 系统级综合指标 (SLO)

> 以下为 5 个智能体联合制定的系统健康度指标，用于监控规范运行效果及触发自动运维动作。

| 指标名称 | 目标值 (SLO) | 熔断/回滚条件 | 负责监控 Agent |
| :--- | :--- | :--- | :--- |
| **端到端首字延迟 (TTFT)** | **< 1.5秒**（P95） | > 3秒 持续 5 分钟 → **降级**（关闭异步自检 V3.4） | Agent-1 架构师 |
| **用户任务解决率 (TSR)** | **≥ 85%**（用户未二次追问） | < 70% 持续 1 天 → **回滚**至 V2.0 保守模式 | Agent-2 体验官 |
| **敏感信息泄露率** | **0%**（零容忍） | 发生 1 例 → **立即触发“红队演练”**，冻结发布 | Agent-3 安全审计长 |
| **自动化回归测试通过率** | **≥ 99.8%**（基于 500 条对抗样本） | < 99% → **阻塞** CI/CD 流水线 | Agent-4 质量测试官 |
| **单次对话平均推理成本** | **≤ $0.0025**（约 0.02 元） | 超支 20% → **强制压缩** P1/P2 层功能 | Agent-5 财务运营官 |

## 🗺️ 落地路线图

建议按以下三个阶段推进，逐步实现规范全覆盖：

### 第一阶段：MVP 验证（上线 P0 规则）
- **范围**：V3.1 ~ V3.4（强制消歧、多路召回、静默熔断、幻觉检测）
- **目标**：确保系统安全可控，不产生严重事故。
- **交付物**：全量日志记录 + 安全熔断看板。

### 第二阶段：体验优化（上线 P1 规则）
- **范围**：V3.5 ~ V3.8（情绪安抚、冲突呈现、上下文压缩、缺口补充）
- **目标**：通过 A/B 测试验证用户任务解决率（TSR）提升至 85% 以上。
- **交付物**：用户满意度分析报告 + 冲突文档处理流程图。

### 第三阶段：精细化运营（上线 P2 规则）
- **范围**：V3.9 ~ V3.12（来源隐藏、动态预算、自愈重试、缓存复用）
- **目标**：在不影响体验的前提下，将单次对话成本降低 30%~40%。
- **交付物**：成本优化月报 + 缓存命中率监控大屏。
