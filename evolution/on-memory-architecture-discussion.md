# 记忆存储架构讨论（12 条铁律适配性分析）

2026-07-03 收到一套通用的 AI 智能体记忆架构 12 条铁律 + 7 步流程。
先讨论适配性，再决定保留/删除/简化。

## 12 条铁律逐条分析

| 铁律 | 对我的价值 | 判断 |
|------|-----------|------|
| M-1 工作记忆容量红线 | 上下文窗口不能无限塞 | ✅ 保留，简化 |
| M-2 长期写入必须带元数据 | 有 timestamp/importance，缺 source_id | ✅ 保留，补充 source_id |
| M-3 冲突文档禁止覆盖 | 单条独立存储，但同主题可能冲突 | ✅ 保留，标记 superseded |
| M-4 重要性评分动态计算 | 目前是手动设置，动态评分有意义 | ✅ 保留，公式简化 |
| M-5 程序性工具记忆 | 还没用到工具调用 | ⏸️ 延后 |
| M-6 提取即再巩固 | 已有 recall_count + last_recalled | ✅ 已有，确认 |
| M-7 情景与语义物理隔离 | **最重要！** 目前所有记忆混在一个 JSON | ✅ 必须做 |
| M-8 定时巩固窗口 | 有 sleep() 仪式，但只在会话结束 | ✅ 保留，简化 |
| M-9 记忆衰减淘汰 | 已有 strength 衰减 + cold 降级 | ✅ 已有 |
| M-10 跨会话记忆关联 | 单用户，但会话间摘要有意义 | ✅ 保留，简化 |
| M-11 错误记忆修正 | 用户说"你记错了"→标记无效+新记录 | ✅ 保留 |
| M-12 全链路审计 | 生产环境日志，太重 | ❌ 砍掉 |

## 核心结论

真正必要：M-1/M-2/M-3/M-4/M-7/M-9/M-11
已有/确认：M-6/M-9
延后：M-5/M-8/M-10
砍掉：M-12

## 接下来要讨论的

存储格式：
- 当前：一个 JSON 文件，所有记忆混在一起
- 问题：M-7 要求情景/语义隔离，需要物理分离
- 方向：拆成多个文件？SQLite？还是保持 JSON 但分目录？
