## 🧠 一、人脑 vs AI 记忆组件映射表

| 人脑系统 | 神经中枢 | AI 智能体对应组件 | 技术实现载体 |
| :--- | :--- | :--- | :--- |
| **感觉记忆** | 感官皮层 | **输入缓冲池** | 流式接收器（Socket/SSE），原始数据暂存（< 500ms） |
| **注意力闸门** | RAS + 丘脑 | **意图识别与过滤引擎** | 轻量级分类模型（< 1B），判定“是否处理”及“优先级” |
| **工作记忆** | 前额叶皮层 | **上下文窗口（核心区）** | LLM 的 `System Prompt + Messages`（当前激活区） |
| **语义记忆**（知识） | 海马体→新皮层 | **向量知识库 + 图谱** | RAG 系统（如 Pinecone/ES），存事实、概念、文档 |
| **情景记忆**（经历） | 海马体 + 前额叶 | **对话历史库 + 摘要记忆流** | 关系型数据库 + 周期性摘要压缩（如 `LangChain SummaryMemory`） |
| **程序性记忆**（技能） | 基底节 + 小脑 | **工具调用注册表（Tool Registry）** | Function Calling 的 Meta 定义及调用日志 |
| **情绪/重要性标记** | 杏仁核 | **元数据标签系统** | 存储 `importance_score`、`emotion_tag`、`urgency_level` |
| **记忆巩固（睡眠）** | 慢波/REM 睡眠 | **异步离线任务** | 定时 CronJob：向量索引重建、全局摘要重算、低分记忆清理 |

## ⚙️ 二、7 步标准实现流程

### Step 1：原始输入接收（感觉记忆缓冲）
- **动作**：接收用户的文字、语音、文件或视觉输入，存入临时缓冲区（Raw Buffer）。
- **有效期**：**≤ 500ms**。超时未处理则丢弃（模拟感官遗忘）。
- **关键设计**：缓冲区不进行任何语义理解，只做格式标准化（如语音转文字、OCR）。

### Step 2：注意力过滤与意图识别（注意力闸门）
- **动作**：执行三级过滤
  1. **是否与我相关**？（判断是否包含唤醒词或明确指令）。
  2. **紧急度评分**（`[0-1]`，如含“立刻”、“紧急”则加权）。
  3. **意图分类**（查询/创作/决策/闲聊）。
- **输出**：若评分低于阈值（如 `0.3`），直接回复“未听清/无需处理”并清空缓冲；若通过，移交工作记忆。

### Step 3：构建工作记忆上下文（加载“桌面”）
- **动作**：将以下内容装入 LLM 的上下文窗口：
  - `System Prompt`（人格设定 + 基础规则）。
  - 当前输入（最新指令）。
  - **最近 N 轮对话**（N 由 Token 预算决定，通常保留 3000-5000 Tokens）。
  - **主动调取的“高亮记忆”**（根据当前意图，从长期记忆中提前预取 Top-3 相关片段）。
- **约束**：总 Token 数必须 ≤ 模型上限的 70%（留下推理生成空间）。

### Step 4：长期记忆检索与路由（对应海马体检索）
- **动作**：并行执行三路检索：
  - **语义检索**（向量库）：找出相关“知识”。
  - **情景检索**（对话库）：找出与当前用户类似的“历史经历”。
  - **工具检索**（程序性记忆）：判断是否需要调用外部 API 或计算工具。
- **冲突处理**：若多路返回矛盾信息，启动 **“权威性仲裁”**（参考铁律：官方 > 个人 > 推断）。

### Step 5：思考推理与策略制定（前额叶综合）
- **动作**：将 Step 3 和 Step 4 的数据合并，送入 LLM 进行推理。
- **强制规范**：必须进行 **“隐藏思维链（CoT）”** 标注，至少包含：
  - `用户显性需求`是什么？
  - `用户隐性需求`（潜台词）可能是什么？
  - 我的回答风险等级（低/中/高）。
- **输出**：生成原始回复草稿（未格式化）。

### Step 6：回复执行与写入情景记忆（输出 + 存盘）
- **动作（双轨并行）**：
  - **对外**：将草稿格式化（添加引用、结构），流式返回给用户。
  - **对内**：**立即将本次交互打包为“情景记忆片段”**，存入情景库。数据包包含：`{用户ID, 时间戳, 用户提问, AI草稿, 情绪标签, 引用来源列表}`。
- **重要性标记**：根据 Step 2 的紧急度 + 用户后续是否有追问，动态计算 `importance_score`，决定其在情景库中的优先级。

### Step 7：记忆巩固与再巩固（异步“睡眠”任务）
- **动作**：这是 AI 的“离线学习期”，发生在空闲时或每日凌晨：
  1. **摘要压缩**：将多轮离散对话合并为“周报/月报”形式的高阶记忆（类似人脑将日常琐事抽象为原则）。
  2. **索引重建**：若知识库新增了大量文档，重新计算向量索引。
  3. **低质遗忘**：删除 `importance_score < 0.2` 且超过 30 天未被调用的记忆片段（模拟海马体清理无用缓存）。
  4. **冲突修正**：若发现新知识与旧记忆冲突，**显式更新旧记录**，并添加“已废弃”标记（避免再次误导）。

## 📜 三、12 条强制铁律（含量化阈值）

| 层级 | 编号 | 铁律名称 | 强制规则描述 | 量化阈值 / 熔断条件 | 技术实现 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **🔴 P0** | **M-1** | **工作记忆容量红线** | 上下文窗口占用不得超过模型上限的 70%。超限时，**强制触发历史摘要压缩**，而非报错。 | `窗口占用率 ≤ 70%`<br>`触发压缩阈值 = 70%` | 每次请求前执行 `tiktoken` 计数，动态裁剪 Messages。 |
| **🔴 P0** | **M-2** | **长期写入必须带元数据** | 任何存入向量库或情景库的信息，**必须**包含 `source_id`、`timestamp`、`embedding_model_version`。缺失则拒绝入库。 | 元数据完整率 = **100%** | JSON Schema 校验器，入库前强制验证字段。 |
| **🔴 P0** | **M-3** | **冲突文档禁止覆盖（仅标记）** | 当发现同一实体存在新信息时，**不得删除旧信息**，只能添加新版本并标记 `superseded_by = new_id`。 | 删除操作数 = **0**（软删除替代硬删除） | 数据库增加 `status` 字段（active/deprecated）。 |
| **🟠 P1** | **M-4** | **重要性评分动态计算** | 每次存入情景记忆时，必须由评分模型打分。分数 = `(0.4 * 用户互动时长) + (0.3 * 紧急度) + (0.3 * 重复提及次数)`。 | 评分范围 [0,1]，>0.7 标记为“核心记忆” | 轻量级 Ranker 模型或启发式规则引擎。 |
| **🟠 P1** | **M-5** | **程序性工具记忆只增不减** | AI 调用过的工具（API），其成功调用记录需存入“程序性记忆库”。后续遇到类似意图，**优先推荐历史上成功过的工具**。 | 工具推荐命中率 ≥ 80% | 基于工具调用日志构建行为序列分析。 |
| **🟠 P1** | **M-6** | **提取即再巩固** | 每次从长期记忆库中召回信息时，**必须在返回给用户前，为本次召回记录增加 1 次“提取权重”**（模拟人脑回忆强化）。 | 提取权重累加，当 > 5 次后该片段优先级自动提升。 | 数据库更新字段 `recall_count` 和 `last_recall_time`。 |
| **🟠 P1** | **M-7** | **情景与语义物理隔离** | 向量库中，**事实性知识（语义）** 与 **交互历史（情景）** 必须分属不同 Collection 或 Prefix，严禁混合检索。 | 检索隔离率 = **100%** | 不同的索引表或不同的命名空间（Namespace）。 |
| **🟢 P2** | **M-8** | **定时巩固窗口** | 每天凌晨 2:00 执行离线“睡眠”任务（压缩摘要 + 重建索引）。执行期间主服务不阻塞。 | 执行时长 ≤ 30 分钟（超时则中断）。 | Kubernetes CronJob 编排。 |
| **🟢 P2** | **M-9** | **记忆衰减淘汰机制** | 满足以下条件的记忆自动归档（非删除）：`importance_score < 0.3` AND `last_recall_time < 当前时间 - 90天`。 | 定期清理，释放存储空间。 | 自动化脚本，每月 1 号执行。 |
| **🟢 P2** | **M-10** | **跨会话记忆关联** | 当新会话开始时，AI 必须检索同一 `user_id` 的历史摘要（非完整对话），并注入工作记忆。 | 检索历史摘要 Token 数 ≤ 500。 | 使用 Map-Reduce 生成用户级“长期偏好摘要”。 |
| **🟢 P2** | **M-11** | **错误记忆修正反馈回路** | 若用户明确反馈“你记错了/上次不是这样的”，**触发强制覆盖**：将错误记录标记为 `invalid`，并在新记录中注释 `corrected_by_user_feedback`。 | 用户纠正触发后，修正操作响应时间 < 1 秒。 | 在线学习机制，即时更新数据库状态。 |
| **🟢 P2** | **M-12** | **记忆操作全链路审计** | 所有“写入、修改、删除、提取”操作，必须生成结构化日志（含操作人、时间、操作类型）。 | 日志留存周期 = **永久**（用于红队演练与故障回溯）。 | ELK / SLS 日志中心。 |

## 🔄 四、端到端全流程时序图（Mermaid）

> **XMind 使用提示**：新建 XMind 文件 -> 点击顶部“插入” -> “代码块” -> 选择语言“Mermaid” -> 将下方代码完整粘贴 -> 点击“预览”或“确定”即可生成可视化脑图/流程图。

```mermaid
sequenceDiagram
    participant User as 用户
    participant Buffer as ① 感觉缓冲池
    participant Gate as ② 注意力闸门
    participant WM as ③ 工作记忆区<br>(上下文窗口)
    participant Semantic as ④a 语义记忆<br>(向量知识库)
    participant Episode as ④b 情景记忆<br>(对话历史库)
    participant Tool as ④c 程序性记忆<br>(工具注册表)
    participant Core as ⑤ 推理引擎<br>(LLM)
    participant Writer as ⑥ 写入器
    participant Offline as ⑦ 离线巩固<br>(CronJob)

    User->>Buffer: 发送信息
    Buffer->>Gate: 传递原始数据(<500ms)
    Gate->>Gate: 意图识别 + 紧急度评分
    alt 评分 < 阈值(0.3)
        Gate-->>User: 忽略/反问
    else 评分 >= 阈值
        Gate->>WM: 加载系统提示词 + 当前输入
        WM->>Semantic: 并行检索 Top-5 知识片段
        WM->>Episode: 并行检索历史相关片段
        WM->>Tool: 检查是否需要调用工具
        Semantic-->>WM: 返回事实性信息
        Episode-->>WM: 返回历史经历
        Tool-->>WM: 返回工具定义
        WM->>Core: 将以上所有注入上下文窗口
        Core->>Core: 执行隐藏思维链推理
        Core-->>User: ⑥ 流式输出最终回复
        par ⑥ 异步写入情景记忆
            Core->>Writer: 打包{用户输入, 输出, 来源}
            Writer->>Episode: 存入情景库(带重要性评分)
        end
    end
    loop ⑦ 每日凌晨 2:00 离线巩固
        Offline->>Offline: 压缩低质对话为摘要
        Offline->>Semantic: 重建向量索引(版本更新)
        Offline->>Episode: 标记低分记忆(小于0.3)为归档
    end
