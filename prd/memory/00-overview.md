# 记忆存储 — 总纲

## 一句话

以天为单位存储原始对话流水账，文件满 10MB 或跨天时触发简化，提炼出核心记忆写入 thamus.json。

## 整体流程

```
┌─────────────────────────────────────────────────┐
│  每次对话：原始消息追加写入当日文件                │
│  格式：问答流水账（类似 thamus.json 单条记录）     │
│  同日多条 → 同一文件（2026070601）               │
│  超 10MB → 开新文件（2026070602）                │
└──────────────────┬──────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────┐
│  简化触发条件（满足任一）：                       │
│  1. 文件达到 10MB                                │
│  2. 跨天（次日第一次对话开始时）                   │
└──────────────────┬──────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────┐
│  简化处理：                                       │
│  1. 扫描当日流水账，筛选有价值内容                 │
│  2. 提炼核心事实/观点/经验 → 写入 thamus.json     │
│  3. 无价值内容 → 直接丢弃                         │
│  4. 计算 embedding、设置 importance、建立 linked  │
└─────────────────────────────────────────────────┘
```

## 存储结构

| 层级 | 文件 | 内容 | 更新时机 |
|------|------|------|---------|
| 流水账 | `memory/logs/YYYYMMDD01.json` | 原始对话记录（问+答） | 每次对话实时追加 |
| 流水账 | `memory/logs/YYYYMMDD02.json` | 当日超 10MB 开新文件 | 同上 |
| 提炼记忆 | `memory/thamus.json` | 简化后的高价值记忆 | 简化时写入 |

## 流水账记录格式

每条记录类似 thamus.json 单条 item，包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| `role` | str | `user` / `assistant` |
| `content` | str | 原始消息内容 |
| `timestamp` | float | 消息时间戳 |
| `id` | str | 消息唯一 ID |

## 提炼记忆格式

沿用现有 thamus.json 格式（content、importance、embedding、linked_ids 等字段）。

## 设计原则

1. **原始先行** — 写入时不简化，保留完整原始数据
2. **定时提炼** — 简化由文件满或跨天触发，不是实时
3. **简化保语义** — 提炼时保留核心事实和上下文，丢弃过程噪音
4. **软删除** — 无价值内容直接丢弃，不保留冷数据
