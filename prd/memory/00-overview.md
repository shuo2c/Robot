# 记忆存储 — 总纲

## 一句话

以天为单位存储对话流水账，每个文件 3MB，满 3MB 开新文件。每个文件内部维护简化提纯、遗忘、固化、双链、向量化等完整记忆机制。

## 整体流程

```
写入阶段：
┌──────────┐    ┌──────────┐    ┌──────────┐
│ 用户提问  │ →  │ 助手回复  │ →  │ 追加到   │
│          │    │          │    │ 当日文件  │
└──────────┘    └──────────┘    └────┬─────┘
                                     │
                              满 3MB / 跨天
                                     │
                                     ▼
简化阶段：
┌─────────────────────────────────────────────────┐
│  1. 扫描 — 读取当日所有文件                      │
│  2. 分类 — LLM 判断类型（事实/观点/经验/噪音）    │
│  3. 提纯 — 压缩冗余内容，保留语义核心             │
│  4. 评分 — LLM 评估 importance [0,1]             │
│  5. 建链 — 建立 linked_ids 关联                  │
│  6. 引用加成 — 被引用越多，importance 越高        │
│  7. 固化 — LLM 判断是否为长期重要记忆             │
│  8. 向量化 — 计算 embedding                      │
│  9. 删除 — importance < 0.3 且 consolidated 的记录删除 │
└─────────────────────────────────────────────────┘
```

## 存储结构

```
memory/
└── logs/
    ├── 2026070601.json    ← 当日第1个文件
    ├── 2026070602.json    ← 当日超3MB，第2个文件
    └── 2026070701.json    ← 次日新文件
```

每个文件既是原始流水账，也是完整记忆存储——包含简化、遗忘、固化、双链、向量化等所有机制。

## 记录格式

一轮对话（用户 + 助手）作为一条记录：

```json
{
  "turn": 1,
  "user": "这个 bug 怎么回事？",
  "assistant": "X 函数的 Y 参数传错了。",
  "timestamp": 1782662400.0,
  "id": "turn_a1b2c3d4e5f6",
  "importance": 0.7,
  "consolidated": true,
  "embedding": [...],
  "linked_ids": ["turn_def456"]
}
```

## 简化触发

| 条件 | 说明 |
|------|------|
| 文件满 3MB | 当前流水账文件超过 3MB |
| 跨天 | 次日第一次对话开始时检测到日期变化 |

## 核心铁律

| 编号 | 铁律 | 说明 |
|------|------|------|
| **F-1** | 没固化不准忘 | consolidated = false 的记录永不删除 |
| **F-2** | 遗忘即删除 | importance < 0.3 且 consolidated = true 的记录直接删除 |
| **F-3** | 元数据完整 | 简化后每条记录必须带 importance、embedding、linked_ids |
| **F-4** | 冲突禁止覆盖 | 发现新版本只标记旧版 deprecated，不删除 |
| **F-5** | 原始数据先行 | 写入时不简化，先存原始对话 |
