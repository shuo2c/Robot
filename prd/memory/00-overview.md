# 记忆存储 — 总纲

## 一句话

以天为单位存储对话流水账，每个文件 3MB，满 3MB 开新文件。每个文件内部维护简化提纯、遗忘、固化、双链、向量化、BM25 检索等完整记忆机制。

## 存储结构

```
memory/
├── logs/
│   ├── 2026070601.json    ← 当日第1个文件，原始对话 + 记忆机制
│   ├── 2026070602.json    ← 当日超3MB，第2个文件
│   └── 2026070701.json    ← 次日新文件
```

## 写入规则

1. 每次对话（用户消息 + 助手回复）打包为一条记录追加到当日文件
2. 同日对话共享文件组，每个文件最大 3MB
3. 超过 3MB 创建新文件：`2026070601` → `2026070602`
4. 跨天后自动切换到新日期文件

## 每个文件的能力

每个日志文件不只是原始记录，它承载完整的记忆机制：

| 能力 | 说明 |
|------|------|
| 简化提纯 | 对话内容压缩，保留语义核心 |
| 遗忘 | 低重要性内容直接删除 |
| 固化 | 重要记忆锁定不淡出 |
| 双链 | 记忆间 linked_ids 关联 |
| 向量化 | 每条记忆有 embedding |
| BM25 检索 | 文件内可搜索 |

## 简化触发

文件满 3MB 或跨天时，对该文件执行简化提纯：压缩冗余内容，提升重要记忆权重，建立双链关联。
