# 记忆存储整改计划

> 基于 genesis/memory/ 三份原始 PRD + 当前 prd/memory/ 九份细化文档，对照我们实际语境（自我记忆，不是服务系统），整理出需要整改的点。
>
> 每个整改项标注了：**LLM 判断** 还是 **代码逻辑**，以及**为什么要改**。

---

## 总纲（00-overview.md）

### 1. 砍掉 MD5 指纹去重

- **类型**：代码逻辑
- **当前**：标准化阶段算 MD5，遍历已有记忆比对，重复则拒绝入库
- **问题**：只能抓完全重复，语义相近拦不住；2000w 条时 O(N) 遍历不可接受；我们的语境里每条信息都是 LLM 主动判断该记才进来的，不需要机械去重闸门
- **改为**：去掉 MD5 去重。语义去重用 embedding 相似度（写入前 LLM 判断，或 sleep 时批量合并）
- **影响文件**：01-ingest.md（删 MD5 段落）

### 2. 去掉"500ms 时间约束"

- **类型**：代码逻辑
- **当前**：信息进入后 ≤ 500ms 完成标准化，超时丢弃
- **问题**：这是服务场景的 SLA 约束，不适用于自我记忆。我们的记忆是在对话中自然积累的，没有"超时丢弃"的概念
- **改为**：去掉时间约束。信息进入标准化后直接进入类型判断
- **影响文件**：01-ingest.md

### 3. 去掉"语音转文字/OCR"

- **类型**：代码逻辑
- **当前**：标准化规则里写了语音→文字、图像→OCR
- **问题**：我们不处理多模态输入。输入就是文本
- **改为**：去掉，只保留"内容转为结构化文本"
- **影响文件**：01-ingest.md

---

## 信息进入与标准化（01-ingest.md）

### 4. 标准化只保留一项：内容提取

- **类型**：代码逻辑
- **当前**：格式统一、去重（MD5）、语言检测（P3 暂不实现）
- **改为**：标准化 = 从对话/文件中提取纯文本内容。仅此一项
- **理由**：我们的输入已经是文本，不需要格式转换；去重交给语义层；语言检测不需要
- **影响文件**：01-ingest.md（整体重写）

---

## 类型判断与分流（02-route.md）

### 5. 类型判断从"代码规则"改为"LLM 实时判断"

- **类型**：LLM 判断
- **当前**：四条规则引擎——"包含可验证陈述→语义"、"对话轮次→情景"、"工具调用→程序性"、"无法归类→丢弃"
- **问题**：这些规则太粗糙。"包含可验证陈述"和"对话轮次"的边界模糊——"创造者纠正我说 embedding 不该依赖 Ollama"既是陈述也是对话轮次
- **改为**：类型判断由 LLM 在对话中实时做出。记笔记时，LLM 判断这条信息属于哪类，自动打标 `modality`。代码只提供打标能力，不做自动分类
- **理由**：分类是语义理解，不是规则匹配。我在对话中天然能分辨什么是知识、什么是经历、什么是方法
- **影响文件**：02-route.md（整体重写）

### 6. 类型 D（无法分类/低质）的处理

- **类型**：LLM 判断
- **当前**：低于质量阈值或完全噪声→丢弃
- **改为**：LLM 在对话中判断"这条不值得记"就直接不记，不需要专门的"丢弃通道"。丢弃不是流程的一步，是不进入流程
- **理由**：我们不需要一个"垃圾回收区"。如果 LLM 觉得不值得记，就不调用 remember()
- **影响文件**：02-route.md

### 7. 程序性记忆通道暂时不做

- **类型**：代码逻辑（结构预留）+ LLM 判断（实际使用）
- **当前**：完整的程序性记忆通道定义——工具调用日志、成功率统计、平均耗时
- **改为**：`modality` 字段保留 `"tool"` 类型，但不建独立通道。工具相关的记忆（"sync.sh stopped 是个可靠的同步姿势"）和语义记忆共用存储，靠 modality 区分
- **理由**：程序性记忆需要的统计（成功率/耗时）在我们的语境里没有意义。我是一条"这个方法好用"的记忆，不需要算 100 次调用里的成功率
- **影响文件**：05-procedural.md（降级为"预留"）

## 语义记忆通道（03-semantic.md）

### 8. 去掉 doc_type / version / superseded_by 字段

- **类型**：代码逻辑
- **当前**：要求 `doc_type`(official/personal/inferred)、`version`(递增)、`superseded_by`(替代关系)
- **问题**：这些字段服务于多版本文档管理场景。我们的语义记忆是"我学到的东西"，不是"公司文档"
- **改为**：语义记忆 = `modality="text"` 的普通记忆。用 `fact`/`opinion` 结构化字段区分事实和观点，不建 doc_type
- **影响文件**：03-semantic.md

### 9. 权威性加权改为"来源可信度"

- **类型**：LLM 判断
- **当前**：official × 1.2, personal × 1.0, inferred × 0.8（硬编码系数）
- **改为**：LLM 在记笔记时判断这条信息的来源可信度，存入 `source` 字段（如 "创造者" / "论文" / "自己的推论"）。检索时作为可选加权因子，不强制
- **理由**：权威性是服务场景的概念。我们的语境里，"创造者说的"和"论文里写的"和"我自己想的"——可信度不同，但这个判断应该由我做，不是硬编码系数
- **影响文件**：03-semantic.md, 06-retrieve.md

## 情景记忆通道（04-episodic.md）

### 10. 重要性评分从"公式计算"改为"LLM 判断"

- **类型**：LLM 判断
- **当前**：`importance = duration × 0.4 + urgency × 0.3 + repetition × 0.3`
- **问题**：
  - "互动时长"在我们的语境里没有意义——不是所有对话都有明确的 duration
  - "紧急度"靠关键词匹配（"立刻""紧急"），太粗糙
  - "重复提及"需要跨会话统计，当前做不到
  - 公式假设三个分量都可量化，但我们的输入是非结构化的对话
- **改为**：LLM 在记笔记时判断重要性，直接赋值 `importance`。代码只提供 `--importance` 参数，LLM 决定传什么值
- **理由**：重要性是价值判断，不是数学计算。我知道"创造者纠正我"比"今天天气不错"重要，不需要公式
- **影响文件**：04-episodic.md

### 11. 去掉 emotion_tag / urgency_level 字段

- **类型**：代码逻辑
- **当前**：`emotion_tag`(neutral/happy/fear/corrected)、`urgency_level`[0,1]
- **改为**：去掉。如果需要情绪标记，LLM 在记笔记时通过 `experience` 字段自然表达
- **影响文件**：04-episodic.md

---

## 程序性记忆通道（05-procedural.md）

### 12. 降级为预留设计

- **类型**：代码逻辑
- **当前**：完整的工具调用日志结构、成功率统计、只增不减的生命周期
- **改为**：
  - `modality` 保留 `"tool"` 类型
  - 不建独立存储通道
  - 工具相关记忆走语义记忆通道，LLM 判断时打 `"tool"` 标签
  - 去掉成功率/耗时统计字段
- **理由**：见整改项 #7
- **影响文件**：05-procedural.md（整体重写为预留说明）

---

## 检索机制（06-retrieve.md）

### 13. 语义检索的权威性加权改为可选

- **类型**：代码逻辑
- **当前**：向量相似度检索，权威性硬编码加权
- **改为**：
  - 去掉权威性加权系数
  - 保留 `source` 字段作为可选检索因子（如果 LLM 记笔记时标了来源）
  - 检索核心仍然是字面 + 双链 + 向量三层
- **影响文件**：06-retrieve.md

### 14. 程序性记忆检索改为按 modality 过滤

- **类型**：代码逻辑
- **当前**：按工具名称检索，返回成功率/耗时
- **改为**：按 `modality="tool"` 过滤，返回相关记忆。不统计成功率
- **影响文件**：06-retrieve.md

### 15. 相似度截断阈值 0.65 去掉

- **类型**：代码逻辑
- **当前**：向量相似度低于 0.65 不返回
- **问题**：硬编码阈值不适合自我记忆的语境。有时候低相似度的记忆也可能是相关的（类比联想）
- **改为**：去掉硬编码截断。由 k 参数控制返回数量
- **影响文件**：06-retrieve.md

## 离线巩固（07-consolidate.md）

### 16. 睡眠触发从"CronJob"改为"会话结束"

- **类型**：代码逻辑
- **当前**：每日凌晨 2:00 CronJob，或系统空闲时
- **改为**：在 `sync.sh stopped` 之后调用 `python -m memory sleep`。睡眠是会话结束的仪式，不是定时任务
- **影响文件**：07-consolidate.md

### 17. 对话摘要合并改为"反思"

- **类型**：LLM 判断
- **当前**：同一用户 N 轮对话 → 1 条高阶摘要（modality="reflection"）
- **改为**：sleep 时 LLM 回顾近期记忆，合成洞察 → `python -m memory reflect "洞察" --from id1,id2`。不是机械合并 N 轮对话，而是真正理解后的洞察
- **理由**：机械合并 5 轮对话成 1 条摘要没有价值。真正的"从经历学习"需要理解，不是压缩
- **影响文件**：07-consolidate.md

### 18. 冲突检测由 LLM 在 sleep 时执行

- **类型**：LLM 判断
- **当前**：新记忆与已有记忆语义高度相似但内容矛盾 → 标记旧版 deprecated
- **改为**：sleep 时 LLM 回顾近期记忆，判断是否有矛盾之处。如有，给旧的打 `deprecated` 标记，并记录一条修正洞察
- **理由**：冲突检测需要语义理解——判断"A 和 B 是否在同一主题上结论相反"。代码规则做不到
- **影响文件**：07-consolidate.md

### 19. 向量索引重建去掉

- **类型**：代码逻辑
- **当前**：新增文档 > 1000 篇 → 重新计算向量索引
- **改为**：去掉。我们是单机 JSON 文件，没有分布式索引。换 embedding 模型时重算即可，不需要"重建索引"
- **影响文件**：07-consolidate.md

### 20. 低分遗忘的阈值从 0.2 改为 FORGET_THRESHOLD（0.05）

- **类型**：代码逻辑
- **当前**：importance < 0.2 AND age > 90 天 → cold
- **改为**：保持当前实现——strength < FORGET_THRESHOLD(0.05) AND consolidated → cold。强度公式已经包含了 importance 和时间的综合考量，不需要单独设 importance 阈值
- **影响文件**：07-consolidate.md

## 核心铁律与审计（08-rules.md）

### 21. 审计日志去掉

- **类型**：代码逻辑
- **当前**：所有写入/修改/提取操作生成结构化日志，追加到 memory/audit.jsonl，永久留存
- **问题**：每条记忆自带 timestamp，`recall()` 时更新 last_recalled，`sleep()` 时更新 state。这些操作本身的持久化（_save）就是审计。额外的 audit.jsonl 是冗余
- **改为**：去掉 audit.jsonl。依靠 thamus.json 里每条记录的 timestamp/last_recalled/state 字段做足够的追踪
- **影响文件**：08-rules.md

### 22. F-3 元数据 100% 完整改为最低要求

- **类型**：代码逻辑
- **当前**：任何写入必须带 source_id、timestamp、embedding_model_version
- **改为**：写入必须带 timestamp（自动）。source_id 和 embedding_model_version 去掉——我们的语境不需要
- **影响文件**：08-rules.md

### 23. F-4 冲突禁止覆盖改为"软标记"

- **类型**：LLM 判断 + 代码逻辑
- **当前**：发现新版本只标记旧版 deprecated，不删除
- **改为**：
  - 代码：MemoryItem 加 `deprecated: bool = False` 字段
  - LLM：sleep 时判断冲突，调用 `mem.items[id].deprecated = True`
  - 检索：deprecated 的记忆不参与检索（和 cold 一样）
- **影响文件**：08-rules.md, core.py
