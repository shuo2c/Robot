# 记忆存储整改计划

> 基于 genesis/memory/ 三份原始 PRD + 当前 prd/memory/ 九份细化文档，对照我们实际语境（自我记忆，不是服务系统），整理出需要整改的点。
>
> 只收录已讨论并达成共识的项。未讨论的暂不加入。

---

## 1. 去掉审计日志

- **涉及文件**：08-rules.md, 00-overview.md
- **当前**：所有写入/修改/提取操作生成结构化日志，追加到 memory/audit.jsonl，永久留存
- **问题**：审计日志的前提是多人协作系统需要追踪"谁在什么时候做了什么"。我们是单人的，每条记忆自带 timestamp，recall 更新 last_recalled，sleep 更新 state——这些字段本身就是足够的追踪
- **改为**：去掉 audit.jsonl。依靠 thamus.json 里每条记录的 timestamp/last_recalled/state 字段做追踪

---

## 2. 信息简化改为异步归档

- **涉及文件**：01-ingest.md
- **当前**：信息进入后 ≤ 500ms 内完成标准化和类型判断，实时做"信息简化"；统一输入格式、MD5 去重、语音/OCR 同步处理
- **问题**：
  - 实时简化来不及做语义提炼，500ms 约束下只能做机械压缩，容易丢上下文
  - 统一输入格式对我们无用——上游 agent/MCP 已经做好格式转化
  - MD5 去重在记忆场景无意义（语义重复抓不住，全量比对性能差）
  - 语音/OCR 是输入层能力，不是记忆存储的职责
- **改为**：
  - 写入时：原始消息直接存入 working 区域，不做简化，不丢数据
  - sleep 时（会话结束触发）：扫描 working 区域，异步执行：
    1. **筛选**：哪些会话值得长期保留
    2. **简化**：把碎片化的思考过程浓缩成连贯记忆，保留"为什么这么想、为什么这么改"
    3. **去重**：用语义相似度（而非 MD5）判断是否与已有记忆重复
  - 去掉 500ms 时间约束
  - 去掉"统一输入格式"步骤
  - 去掉语音/OCR 要求
